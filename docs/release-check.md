## Playwright

`scripts/check_browser.cjs` использует Chrome, блокирует внешнюю HTTP-сеть и
не вызывает AI. Проверены:

1. Открытие очереди всех 70 сборщиков и выбор первого по приоритету.
2. Крупнейший отправитель по исходным рёбрам и переход в его карточку.
3. Точный поиск длинного gid, предупреждение о границе и неизвестный номер.
4. Отрисовка полного графа, кнопки фокусировки, масштаба и всей схемы.
5. Отсутствие внешних script/link ресурсов графа.
6. Локальная дневная SVG-диаграмма и отсутствие JavaScript/Streamlit ошибок.

Обнаружены и исправлены: округление номера в тестовой фикстуре и ошибка
JavaScript диаграммы при смене клиента. В приложении сохранён точный gid.
Дневной график теперь локальный SVG; точные дневные данные остаются в таблице.
Снимок: out/browser-review.png.

Для повторения нужны Node.js, Playwright и Chrome:

```bash
npm install --prefix /tmp/50tenge-browser-check playwright@1.63.0 --ignore-scripts
NODE_PATH=/tmp/50tenge-browser-check/node_modules APP_URL=http://127.0.0.1:8501 node scripts/check_browser.cjs
```

По умолчанию путь Chrome соответствует macOS. Для другой системы задать
CHROME_PATH. Python — .venv/bin/python, можно переопределить переменной PYTHON.

## Живой AI

Команда: `python scripts/check_live_ai.py --live`. Она явно разрешает
платные запросы и читает локальный ключ, не выводя его.

Проверены два вопроса с gpt-4.1-mini:

- Объяснение выбранного клиента: схема и ссылки на факты прошли проверку;
  суммы, число контрагентов и переводов сверены. 2215 входных, 276 выходных
  токенов. Модель повторила числа вопреки инструкции о краткой интерпретации;
  это ограничение соблюдения стиля, числовой ошибки в этом ответе не найдено.
- Общие прямые получатели: агент вызвал common_recipients, вернул клиента
  100000003684369100 и две связи с 49 500 и 50 000 KZT. Они совпали с данными.
  1375 входных и 183 выходных токена за цикл агента.

Всего в этой проверке 4049 токенов API. Это не расход токенов текущего чата Codex.
Ошибки авторизации, лимитов, некорректного ответа и отказа проверяются заглушками
в тестах; реальные сбои сервиса искусственно не создавались.
Два успешных вопроса не гарантируют правильность любого будущего ответа.
Использованы официальные описания [структурированных ответов](https://developers.openai.com/api/docs/guides/structured-outputs)
и [вызова функций](https://developers.openai.com/api/docs/guides/function-calling).

## Комплект сдачи и защита

`python scripts/build_submission.py` создаёт out/submission.zip с тремя CSV,
метаданными, схемой, инструкциями, сценарием и manifest (коммит, dirty-флаг, SHA256).
Исходный код передаётся ссылкой на репозиторий. Исходные parquet и ключи в архив
не добавляются. Гипотезы групп и пороги описаны в cluster-hypotheses.md.
Сценарий защиты и ответы на вопросы — demo.md.

## Что нельзя считать выполненным автоматически

Playwright подтверждает работоспособность сценария, но не понятность для нового
пользователя. Проверки с действующим AML-специалистом и человеческой пятиминутной
репетиции пока нет. Текст и техническая проверка подготовлены; команде нужно
произнести выступление и отработать неожиданный gid. Нельзя обещать 100 баллов
или измеренную точность выявления преступной деятельности.
