# Запросы к графу и AI-агент

Модуль `viz/graph_agent.py` подключается вызовом
`render_graph_agent(roles, edges, selected_gid)`. Таблицы берутся из готового
пайплайна; роли и приоритеты агент не пересчитывает.

## Локальный сценарий

Введите 2–10 разных полных gid через запятую, выберите глубину 1–4 и нажмите
«Найти общих получателей». Ключ и интернет не нужны. Поиск выполняет BFS от
каждого источника по направлению переводов. Получатель должен быть достижим
от **всех** источников; сами исходные клиенты исключаются из ответа.

Показываются до 20 результатов, упорядоченных по готовому приоритету,
при равенстве — по gid. Для каждого есть один кратчайший путь от каждого
источника с направлениями, суммами и числом переводов каждой связи.
Отдельно указывается полное число совпадений и число скрытых результатов.

## AI-сценарий

Настройки читает `viz.ai_transport.read_config`: переменные окружения имеют
приоритет над корневым `.env`. Нужен `OPENAI_API_KEY`; `OPENAI_MODEL` по умолчанию
равен `gpt-4.1-mini`. API вызывается только после нажатия кнопки.

Модель получает вопрос и выбранный gid, затем сама выбирает одну или несколько
разрешённых функций:

| Функция | Результат |
|---|---|
| `lookup_node(gid)` | Готовая карточка выбранного клиента |
| `common_recipients(gids, max_hops)` | Общие достижимые получатели с маршрутами |
| `find_path(src, dst, max_hops)` | Один кратчайший направленный путь до 4 шагов |
| `rank_cluster(cluster_id, limit)` | До 20 клиентов кластера по приоритету |

Все параметры проверяются локально. Выполняются только эти функции;
сгенерированный код, произвольные выражения или запросы не исполняются.
Идентификаторы передаются строками без потери точности int64.

В первом запросе `tool_choice=required`. Результаты реальных операций
возвращаются в Responses API через `function_call_output`. История передаётся
явно, `store=false`. Не более 3 запросов, 6 вызовов функций, 1200 выходных
токенов на запрос, тайм-аут запроса до 20 секунд с общим бюджетом около минуты.
Третий запрос допускает только окончательный ответ. Автоматических повторов нет.

Экран показывает объяснение, раскрываемые аргументы и результаты каждой
операции, суммарное число входных/выходных токенов. Кнопки открывают клиентов
из результатов: callback меняет `client_search` до автоматического перезапуска
страницы Streamlit. До пяти ответов сохраняются в памяти текущей сессии;
ключ кэша включает вопрос, выбранного клиента, модель, инструкции и данные.

## Ограничения

Направленный путь означает структурную достижимость. Даты отдельных переводов
не проверяются: путь не доказывает движение тех же денег. Общий получатель
не становится автоматически организатором. Отсутствие пути относится только
к заданной глубине и наблюдаемой выборке. Граница четвёртого колена, другие
банки, период и порог 5000 KZT ограничивают полноту данных.

Текст модели может содержать ошибку интерпретации: первичным доказательством
служат открытые результаты инструментов. Инструкции запрещают обвинения,
изменение ролей и неподтверждённые факты, но не гарантируют истинность каждого
предложения модели. Ошибки API отображаются без тела ответа и без ключа.

Реализация основана на [официальном описании function calling](https://developers.openai.com/api/docs/guides/function-calling).
В рамках добавления модуля тесты и платные запросы API не запускались.
