# Повторяющиеся маршруты, короткие циклы и удаление узлов

Дополнительный анализ выполняет `pipeline.routes.analyze_routes(G, transactions, scored)`.
Результат — JSON-совместимый словарь с разделами `recurring_routes`, `short_cycles`,
`resilience`. Все идентификаторы клиентов сериализуются строками без потери int64.
Исходные таблицы, роли и приоритеты не изменяются. Новых зависимостей нет.

## Повторяющиеся A→B→C

Три клиента различаются. На каждом участке должно быть не менее двух транзакций
за период. Входящие A→B агрегируются по календарным дням. Для каждого такого дня
проверяются переводы B→C через один и два дня. Маршрут проходит критерий, если
есть хотя бы два разных входящих дня с последующим выходом в этом окне.

Переводы в тот же день исключены: дневная точность не позволяет установить
внутридневной порядок. Один исходящий день может соответствовать нескольким
входящим дням; это подсчёт наблюдаемых сочетаний дат, не взаимно-однозначное
сопоставление отдельных операций и не доказательство движения тех же денег.

Результат хранит числа переводов и полные суммы каждого участка, число
подходящих входящих дней, число пар дат и до шести примеров с датами, суммами
и количеством операций за день. `evidence_total` и `evidence_truncated`
объясняют сокращение примеров. Суммы участков относятся ко всему периоду,
а не только к показанным дням.

Сортировка: подходящие входящие дни по убыванию, сумма двух участков по
убыванию, затем номера клиентов по возрастанию. Сохраняются первые 100;
`eligible_total`, `candidate_total`, `limit` и `truncated` показывают охват.

## Направленные циклы длины 2 и 3

Проверяются только соседние направленные рёбра. Самопереводы исключены.
Начало цикла — минимальный gid, поэтому циклические сдвиги не дублируются.
Противоположные направления треугольника считаются разными циклами.

Для каждого цикла сохраняются его узлы и исходные суммы/количества операций
по каждому ребру. Сумма рёбер используется для сортировки, затем длина и gid
разрешают ничью. Вывод ограничен 100 циклами, полное число найденных и
численность по длинам указаны отдельно. Неограниченный `simple_cycles`
не используется. Циклы длиннее трёх не рассматриваются.

Это циклы агрегированного графа за период. Временной порядок операций не
проверяется, возврат тех же денег не установлен. Сумма рёбер не равна сумме
уникальных денег и не является оценкой отмывания.

## Сценарии удаления

Удаляются первые N узлов полного рейтинга: N=1,3,5,10,20. Рейтинг сортируется
по убыванию `priority_score`, при равенстве — по gid; seed не исключаются.
Для маленького графа N ограничивается его размером, повторяющиеся N удаляются.

До и после удаления считаются:

- Число оставшихся узлов, рёбер и слабосвязных компонент.
- Размер крупнейшей компоненты и её доля среди оставшихся узлов.
- Сохранённая сумма весов направленных рёбер и доля исходной суммы.
- Сколько узлов удалено из исходной крупнейшей компоненты, сколько осталось,
  на сколько частей она распалась, размер крупнейшей оставшейся части и число
  сохранившихся узлов вне этой части.

Последние показатели отделяют простое удаление узлов от фрагментации:
`original_largest_nodes_outside_largest_fragment` не включает удалённых клиентов.
Нулевая оставшаяся сеть имеет нулевые размеры, доли и число компонент.
Если крупнейших исходных компонент несколько, выбирается компонент с меньшим
минимальным gid, обеспечивая повторяемость.

Для каждого N выполняются 20 случайных удалений такого же размера,
`random.Random(42)`. Внутри набора узлы не повторяются; наборы разных запусков
могут совпасть. Выводятся средний, минимальный и максимальный размеры крупнейшей
оставшейся компоненты и отличие целевого удаления от случайного среднего.

Слабая связность не равна направленной достижимости денежных потоков.
Утраченная сумма рёбер — сумма наблюдаемых переводов на удалённых связях,
не обещание предотвращения будущих переводов. Результат описывает только
наблюдаемую сеть, не гарантирует разрушение реальной инфраструктуры.

## Вычислительные ограничения и статус

Обход маршрутов и треугольников ограничен длиной два/три и локальными
списками соседей; матрица всех пар не создаётся. Число двухшаговых кандидатов
зависит от суммы произведений входящей и исходящей степеней. На плотных графах
этот этап потребует дополнительного ограничения; целевой размер — текущая
выгрузка хакатона. Для результатов используются кучи длиной не более 100;
все подходящие кандидаты считаются, даже если не попали в вывод.

Расчёт использует обычные обходы компонент для 20 случайных наборов каждого N.
Общие ограничения данных: другие банки, периоды, глубина за четвёртым шагом
и суммы ниже 5 000 KZT невидимы. Входящие извне выборки могут отсутствовать.

После интеграции полный пайплайн на реальных данных завершился за 4.42 с,
включая все бонусные расчёты. Найдено 112 повторяющихся маршрутов, 177 циклов
длины два и 41 цикл длины три. После удаления топ-20 крупнейшая часть содержит
1279 клиентов против среднего 1841.15 при случайном удалении; исходно — 1877.
Новые модульные тесты и браузерная проверка этой версии не выполнялись.
