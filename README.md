# Граф денег — команда 50 Tenge

Локальный аналитический инструмент: три обезличенных parquet-файла → направленный граф → объяснимые роли и приоритет проверки → три CSV и экран сети. Результаты являются гипотезами для проверки, а не обвинениями.

## Подготовка

Проверено на Python 3.14. Поместите `nodes.parquet`, `edges.parquet`, `transactions.parquet` в `data/`.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

В Windows PowerShell вместо `source` используйте `.\.venv\Scripts\Activate.ps1`. Зависимости ставятся один раз; расчёт от исходных данных до трёх CSV выполняется одной командой:

```bash
python run.py --data data --out out
```

Результаты: `out/nodes_roles.csv` (каждый gid), `out/clusters.csv` (сводка по сообществам), `out/top_nodes.csv` (30 узлов по приоритету) и `out/run_metadata.json` (фактические пороги, версии, время расчёта). Для экрана:

```bash
streamlit run viz/app.py
```

Экран построен вокруг проверки клиента: выберите его из очереди или найдите по полному номеру, прочитайте причину приоритета, посмотрите суммы и связи. Для первого знакомства включите «❔ Как пользоваться» в боковой панели. Во вкладке «Группа клиентов» можно сразу увидеть всех участников группы или выбрать одного либо несколько по номеру; выбранный набор скачивается отдельным CSV. Роли и колонки подписаны по-русски; «исходный клиент дела» обозначает seed, «группа» — кластер. Приоритет показан в баллах из 100 и не является вероятностью нарушения. Фильтры охватывают все 2 248 узлов, включая изоляты; официальный top-30 доступен отдельно. Точные правила, пороги и метрики раскрываются в деталях расчёта. Граф позволяет переключать окраску по ролям и группам, показывает направление переводов и легенду. Для больших окружений показ ограничен 200 связными узлами; расчёты используют полный граф. JS-ресурсы графа встроены, интернет для просмотра не нужен.

### Навигация по экрану

Во вкладке «Группа клиента» доступна устойчивость состава по десяти повторным
запускам, спорные участники и направленные переводы между соседними группами.
Эти показатели пересчитываются обычной командой пайплайна; старые выгрузки
нужно обновить. Оценка устойчивости не является вероятностью нарушения.
Метод, пороги и сравнение экспериментального согласованного разбиения —
в [docs/ranking.md](docs/ranking.md#устойчивость-групп-и-спорные-участники).

Слева расположены фильтры и выгрузки. В основном окне — точный поиск по номеру,
очередь проверки и карточка выбранного клиента. При ручном поиске выбор из очереди
отключается; кнопка «Вернуться к очереди» очищает поиск. Фильтры можно сбросить
одной кнопкой. Вкладки: «Схема связей», «Переводы», «Группа клиента», «Помощник»,
«Расчёт и основания». Все исходные функции доступны в этих разделах.

Тема интерфейса хранится в `.streamlit/config.toml` и включена в Docker-образ.
После изменения темы при необходимости перезапустите Streamlit и обновите
страницу. Пользовательская тема, выбранная в настройках Streamlit, может
переопределять тему проекта.

## AI-помощник OpenAI (опционально)

В карточке клиента помощник объясняет готовые расчёты по вопросу аналитика.
В OpenAI отправляются вопрос, показатели выбранного клиента и до 10 крупнейших
входящих и исходящих связей. Полный датасет не отправляется. Ответ модели нужно
сверять с раскрываемыми исходными показателями: модель может ошибаться.
Роли, рейтинг и CSV рассчитываются локально, без API; помощник их не изменяет.

Для macOS / zsh задайте ключ в том же терминале, из которого запускаете экран
(вставляемый ключ не отображается; не помещайте его в код или переписку):

```zsh
read -s "OPENAI_API_KEY?Вставьте ключ OpenAI и нажмите Enter: "
export OPENAI_API_KEY
.venv/bin/python -m streamlit run viz/app.py
```

Если экран уже запущен, остановите его через Ctrl+C и запустите снова из этого
терминала. Модель по умолчанию — `gpt-4.1-mini`; можно задать `OPENAI_MODEL`.
Нужны активные API-кредиты и доступ к выбранной модели. Также можно сохранить
`OPENAI_API_KEY=...` и `OPENAI_MODEL=gpt-4.1-mini` в корневом `.env`; переменные
окружения имеют приоритет. `.env` исключён из Git. Запрос выполняется только по кнопке;
после ответа отображается расход токенов, полученный от API.
Без ключа остальные функции экрана доступны. Дополнительных зависимостей нет.

Подключение использует [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text),
`store=false`, ограничение ответа 1600 токенов и сетевой таймаут 30 секунд.
Факты, число переводов/контрагентов, суммы и ограничения выводятся локальными
шаблонами. AI возвращает объяснение, ссылки на идентификаторы фактов и следующие
шаги через [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Приложение проверяет формат ответа и существование указанных источников;
числа для сверки доступны в отдельном блоке фактов. Наличие цифр в тексте само по себе не блокирует ответ.
это не гарантирует смысловую правильность текста модели. Неполный ответ, отказ
или неизвестные источники не показываются как готовое объяснение.
До 10 ответов сохраняются в текущей сессии: тот же вопрос по тем же данным и
модели повторно не отправляется. Изменение инструкций также сбрасывает совпадение.
Справку с фактами, ограничениями и черновиком AI можно скачать в TXT.
Это помощник для объяснения карточки; самостоятельный поиск по всему графу
через вызовы инструментов в этой версии не реализован.

## Docker Compose

При запущенном Docker Engine из корня репозитория:

```bash
docker compose run --build --rm pipeline
docker compose up --build dashboard
```

Экран откроется на `http://localhost:8501`. `data/` подключается только для чтения, `out/` сохраняется на хосте. Сначала выполните расчёт CSV, затем запускайте экран.

## Как читать результат

Роль определяется правилами по наблюдаемым метрикам, применяемыми в таком порядке: изолят; консолидация на границе; неизвестный узел на границе; координатор; консолидация; распределитель; конечный получатель; транзит; остальные. Например, консолидация требует не менее трёх разных отправителей и входящей суммы не ниже 75-го процентиля положительных входящих сумм non-seed. Распределитель имеет не менее пяти получателей. Транзитный узел отдаёт 70–130% наблюдаемого входа. Пороги и полный порядок условий находятся в [docs/roles.md](docs/roles.md); фактические вычисленные процентили записаны в `out/run_metadata.json`.

Приоритет = `0.35 × объём + 0.30 × посредничество + 0.20 × достижимость от seed + 0.15 × степень`. Объём и степень оцениваются по исходящим связям у seed, а у остальных — по входящим и исходящим согласно [docs/ranking.md](docs/ranking.md). `role_score` и `priority_score` — относительные оценки по правилам, не вероятность виновности.

Граница обхода на глубине 4 не доказывает, что деньги остались у получателя. Входящие переводы seed и других узлов могут отсутствовать вне выборки. Переводы ниже 5 000 KZT, другие банки и периоды не видны. Направление перевода сохраняется для ролей и на экране; только кластеризация использует неориентированную проекцию. `cluster_id` обозначает сообщество, его описание — гипотеза. Данные не содержат личности клиента и не позволяют оценить точность ролей без независимой разметки.

Для значительно большего графа следует сначала измерить время, затем перейти к приближённому betweenness и более быстрым графовым реализациям. Схема решения: [docs/scheme.md](docs/scheme.md), готовый SVG для слайда: [docs/scheme.svg](docs/scheme.svg).

Проверка на локальной машине с Python 3.14 и pandas 2.3.3: `python run.py --data data --out out` дал 2 248 узлов, 107 кластеров, top-30 менее чем за 2 с; 96 тестов прошли, два запуска дали одинаковые CSV. Экран проверен на пяти gid, включая изолят и границу. `docker compose run --build --rm pipeline` успешно собрал образ и записал те же CSV побайтово. `docker compose up --build -d dashboard` поднял экран на `http://localhost:8501`; Chrome отрисовал граф в режиме кластеров без ошибок страницы.
