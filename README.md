# Граф денег — команда 50 Tenge

Локальный аналитический инструмент: три обезличенных parquet-файла → направленный граф → объяснимые роли и приоритет проверки → три CSV и экран сети. Результаты являются гипотезами для проверки, а не обвинениями.

## Подготовка

Проверено на Python 3.14. Поместите `nodes.parquet`, `edges.parquet`, `transactions.parquet` в `data/`.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

В Windows PowerShell вместо `source` используйте `.\.venv\Scripts\Activate.ps1`. Зависимости ставятся один раз; расчёт от исходных данных до трёх CSV выполняется одной командой:

```bash
python run.py --data data --out out
```

Результаты: `out/nodes_roles.csv` (каждый gid), `out/clusters.csv` (сводка по сообществам), `out/top_nodes.csv` (30 узлов по приоритету) и `out/run_metadata.json` (фактические пороги, версии, время расчёта). Для экрана:

```bash
streamlit run viz/app.py
```

Экран ищет любой gid, включая изоляты, показывает официальный top-30 и отдельный список **всех** узлов с фильтрами по роли, кластеру и seed. Карточка объясняет роль и вклады в приоритет, кластер и направленное окружение на 1–2 шага. Граф переключается между цветом по роли и по кластеру; в подсказке узла есть номер кластера. Для больших окружений показ ограничен 200 связными узлами; расчёты используют полный граф. Граф работает с встроенными JS-ресурсами без интернета.

## Docker Compose

При запущенном Docker Engine из корня репозитория:

```bash
docker compose run --build --rm pipeline
docker compose up --build dashboard
```

Экран откроется на `http://localhost:8501`. `data/` подключается только для чтения, `out/` сохраняется на хосте. Сначала выполните расчёт CSV, затем запускайте экран.

## Как читать результат

Роль определяется правилами по наблюдаемым метрикам, применяемыми в таком порядке: изолят; консолидация на границе; неизвестный узел на границе; координатор; консолидация; распределитель; конечный получатель; транзит; остальные. Например, консолидация требует не менее трёх разных отправителей и входящей суммы не ниже 75-го процентиля положительных входящих сумм non-seed. Распределитель имеет не менее пяти получателей. Транзитный узел отдаёт 70–130% наблюдаемого входа. Пороги и полный порядок условий находятся в [docs/roles.md](docs/roles.md); фактические вычисленные процентили записаны в `out/run_metadata.json`.

Приоритет = `0.35 × объём + 0.30 × посредничество + 0.20 × достижимость от seed + 0.15 × степень`. Объём и степень оцениваются по исходящим связям у seed, а у остальных — по входящим и исходящим согласно [docs/ranking.md](docs/ranking.md). `role_score` и `priority_score` — относительные оценки по правилам, не вероятность виновности.

Граница обхода на глубине 4 не доказывает, что деньги остались у получателя. Входящие переводы seed и других узлов могут отсутствовать вне выборки. Переводы ниже 5 000 KZT, другие банки и периоды не видны. Направление перевода сохраняется для ролей и на экране; только кластеризация использует неориентированную проекцию. `cluster_id` обозначает сообщество, его описание — гипотеза. Данные не содержат личности клиента и не позволяют оценить точность ролей без независимой разметки.

Для значительно большего графа следует сначала измерить время, затем перейти к приближённому betweenness и более быстрым графовым реализациям. Схема решения: [docs/scheme.md](docs/scheme.md), готовый SVG для слайда: [docs/scheme.svg](docs/scheme.svg).

Проверка на локальной машине с Python 3.14 и pandas 2.3.3: `python run.py --data data --out out` дал 2 248 узлов, 107 кластеров, top-30 менее чем за 2 с; 96 тестов прошли, два запуска дали одинаковые CSV. Экран проверен на пяти gid, включая изолят и границу. `docker compose run --build --rm pipeline` успешно собрал образ и записал те же CSV побайтово. `docker compose up --build -d dashboard` поднял экран на `http://localhost:8501`; Chrome отрисовал граф в режиме кластеров без ошибок страницы.
